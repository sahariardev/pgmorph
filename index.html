Safe Constraints

Adds CHECK and FOREIGN KEY constraints using NOT VALID to avoid heavy locking. Validates background data separately.

Smart Not-Null

Migration workflow for adding NOT NULL constraints to existing columns without full table rewrites or long locks.

Retry & Backoff

Intelligent lock acquisition strategy with configurable timeouts and exponential backoff to ensure success.

CLI Command Reference

# Introspect a table
$ pgmorph introspect --table users

# Add a column safely
$ pgmorph add-column \
    --table users \
    --column bio \
    --type text \
    --default "'no bio'"

# Add a check constraint without locking
$ pgmorph add-check \
    --table users \
    --constraint-name email_check \
    --rule "email ~* '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$'"

# Add a foreign key without locking the table
$ pgmorph add-foreign-key \
    --table orders \
    --column user_id \
    --foreign-table-name users \
    --foreign-column-name id \
    --on-delete cascade

# Set NOT NULL safely on an existing column
$ pgmorph set-not-null \
    --table users \
    --column email

# Preview any command with dry-run
$ pgmorph add-column --table users --column bio --type text --dry-run

Native Rust Library

use pgmorph::db::{connect, direct::add_column};
use pgmorph::config::MigrationConfig;

let client = connect("...").await?;
let config = MigrationConfig::default();

add_column(&client, &config, &AddColumnArgs {
    table: "users".into(),
    column: "active".into(),
    data_type: "boolean".into(),
    default: Some("true".into()),
    ..Default::default()
}).await?;
